# 增强盘可读性与全国三级出生地设计

## 背景

当前增强盘在宽屏上存在明显的可读性问题：宫位、图例和辅助信息大量使用 `8–11px` 字号，AI 解读正文仅为 `11px`。出生地为手工维护的省市二级列表，安徽省缺少池州、宣城，且无法选择县、区。现有真太阳时校正使用市级经度，因此单纯增加县区名称不能实现真正的县区级精度。

## 目标

1. 统一提升整个增强盘的字号、行高、控件尺寸和宽屏布局可读性。
2. 将出生地扩展为覆盖全国的“省—市—县/区”三级联动。
3. 使用县区中心经度计算真太阳时；县区数据缺失时有明确、可测试的逐级回退。
4. 保持旧的省市出生信息、增强盘排盘和 AI 解读 API 兼容。

## 非目标

- 不增加乡镇、街道或村级选择。
- 不在运行时请求第三方地图、地理编码或行政区 API。
- 不改动排盘算法、星曜规则、AI 提示词或 P12 安全策略。
- 不趁机重设首页、标准盘或合盘的视觉风格。

## 设计方案

### 1. 增强盘排版

保留现有色彩、国风视觉和信息层级，仅调整可读性与响应式布局。

| 区域 | 当前常见字号 | 设计基线 |
| --- | --- | --- |
| 时间导航、显示模式、主操作 | `9–12px` | `13–14px`，主要按钮高度不低于 `36px` |
| 命盘标题 | `10–14px` | 辅标 `12px`，主标 `16px` |
| 宫位、干支、年龄段 | `8–10px` | 辅助信息不低于 `11px`，宫位名 `13px` |
| 主星与四化 | `10–12px` | 主星 `14px`，其他星曜 `12px` |
| 图例和操作提示 | `9px` | `12px` |
| AI 频道按钮 | `10px` | `13px` |
| AI 解读标题 | `11px` | `15px`，加粗 |
| AI 解读正文 | `11px` | `15px`，行高 `1.8` |
| 追问输入和提示 | `10–11px` | `14px` |

宽屏下页面内容最大宽度由 `1280px` 提升到约 `1500px`，AI 解读栏由 `380px` 提升到约 `440px`，两栏间距为 `24px`。较窄桌面和平板屏幕不强行压缩命盘，在合适断点改为上下排列：命盘在上，AI 解读在下。移动端保持单列并允许命盘区域自适应缩放，不产生整页水平滚动。

### 2. 全国三级行政区数据

生产运行时使用仓库内置、已精简的数据快照，每个节点仅保留：

- 行政区划代码 `code`
- 名称 `name`
- 中心经度 `longitude`
- 下级节点 `children`

数据生成时合并两类来源：

1. 行政区层级和代码：`modood/Administrative-divisions-of-China` 的省市县数据。
2. 行政区中心坐标：MIT 许可的 `zhChuXiao/ChinaGeoJson` / DataV GeoAtlas `info.json`。

快照必须固定上源 commit，在数据头信息中保留生成日期、来源 URL 和 commit SHA。上源更新只能通过明确的生成脚本完成，不允许在页面运行期临时拉取。

直辖市和省直辖县级单位对前端统一暴露三级选择结构。直辖市的市级显示自身名称，第三级显示各区县；省直辖县级单位使用数据源中的实际分组。

### 3. 表单与数据流

`BirthFormState` 增加 `district` 和 `locationCode`；`BirthInfo` 增加可选的 `district`、`locationCode`。

三级联动规则：

1. 选择省份后清空市、县区和位置代码，不自动选择第一个市。
2. 选择市后清空县区和位置代码，不自动选择第一个县区。
3. 选择县区后，保存完整三级名称、代码和县区中心经度。
4. 用户不填出生地时保持现有可选行为；一旦选择省份，必须完成市和县区选择，才能提交精确位置。
5. 完整地址在摘要、分享信息和标准盘显示为“安徽省 / 池州市 / 贵池区”。

经度选择顺序为：县区中心经度 → 市级中心经度 → 省级中心经度 → 北京时间基准经度 `120°E`。回退发生时，表单应明确显示当前使用的精度级别，不静默伪装为县区级精度。

### 4. 兼容性

- 旧数据中只有 `province` 和 `city` 时，仍可正常排盘，并使用旧的市级经度。
- 现有 `birthInfoToChartInput` 和 AI 解读请求不强制增加县区字段，避免改变当前 API 合约。
- 增强盘和标准盘使用同一经度和真太阳时结果，不允许两种盘因地点数据不同步而产生差异。

## 错误处理

- 省、市或县区在快照中找不到对应子节点时，不保留已失效的下级选择。
- 用户已选省但未完成市、县区时，表单给出字段级错误且不提交。
- 坐标缺失或非有限数字时，按规定逐级回退并显示“市级估算”或“省级估算”。
- 数据生成脚本对重复代码、空名称、断裂父子关系、非法经度和安徽省基准数据失配必须失败退出。

## 测试设计

### 数据契约测试

- 全国省级节点无重复代码且关键字段非空。
- 每个市、县区都能追溯到唯一父节点。
- 所有经度为有限数字且落在中国合理范围内。
- 安徽省包含 16 个地级市，包括池州市和宣城市。
- 池州市至少包含贵池区、东至县、石台县、青阳县，且各自有可用经度。

### 表单行为测试

- 选择安徽省后可选池州市，选择池州市后可选贵池区。
- 更换省份会清空原市和县区；更换市会清空原县区。
- 三级选择完成后，提交值包含完整名称、行政区代码和县区经度。
- 只选省或只选省市时，显示校验信息且不提交。
- 旧的二级初始数据仍能渲染与提交。

### 排版和浏览器验收

- 桌面宽屏下 AI 正文计算字号不小于 `15px`，宫位辅助文字不小于 `11px`。
- `1440px` 和 `1920px` 宽度下两栏布局无重叠、裁切和整页水平滚动。
- `1024px` 附近正确转换为单列布局。
- `375px` 移动端可完成三级选择、起盘和阅读 AI 解读，不出现遮挡。
- 深色、浅色主题的正文、标签、禁用态和错误态均保持可辨识对比度。

## 验收标准

1. 生产用户可以选择“安徽省 → 池州市 → 贵池区”及全国其他有效县区。
2. 选中县区后，真太阳时使用该县区中心经度，并在表单中可见。
3. 增强盘所有主要阅读区域达到本文字号基线，不以浏览器缩放作为解决方案。
4. 增强盘、标准盘、ChartFacts 和 AI 解读使用同一份出生信息和真太阳时结果。
5. 新增测试、现有 P1–P12 回归、类型检查和生产构建全部通过，并通过桌面与移动端浏览器验收。
